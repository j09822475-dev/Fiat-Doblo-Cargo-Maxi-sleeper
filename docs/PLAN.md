# План: система проектирования кузова (на примере Fiat Doblò Cargo Maxi)

Цель: вместо одной 3D-модели сделать веб-систему для работы с проектом кузова.
Кузов собирается из отдельных деталей со своими данными. Их можно смотреть по
слоям и узлам. Система сама находит **коллизии** (детали пересекаются),
**недостаточные зазоры** (детали ближе нормы) и **увеличенные зазоры** (детали
дальше нормы: щели между дверью и проёмом, между фарой и крылом и т. п.).
Нормы по умолчанию берутся из инженерных справочников и стандартов, а в
проекте их можно переопределить.

Текущая модель (`js/car.js`) в новую систему не переносится. Из неё берём
только проверенные габариты: 4740 × 1832 × 1845 мм, база 3105 мм, колея
1530 мм, положения дверей и стёкол, сверенные с чертежом Doblò 2015 Cargo LWB.

---

## 1. Что умеет система (требования)

### 1.1 Проект и состав изделия
- Проект — файл `project.json`: параметры машины, дерево изделия, нормы,
  результаты проверок и история изменений (через git).
- Дерево изделия: **изделие → система → узел → деталь**. Пример:
  `Кузов в белом → Боковина правая → Панель боковины наружная`.
- У каждой детали есть:
  - `id` — код детали в стиле каталога, например `BIW-SIDE-R-OUT`;
  - название, система (слой), узел-родитель;
  - материал и толщина листа, масса (считается по объёму);
  - источник геометрии: параметрический генератор или импортированный файл;
  - кинематика: неподвижная, шарнир (ось, углы), сдвижная (траектория), подвеска/руль;
  - класс допуска и ссылки на правила зазоров, в которых деталь участвует;
  - статус: черновик, проверено, утверждено.

### 1.2 Послойный просмотр
- Панель слоёв и дерево изделия с чекбоксами «показать», «прозрачно»,
  «изолировать» (показать только выбранное) и «заблокировать».
- Слои по умолчанию:
  1. Каркас кузова в белом (BIW): пол, лонжероны, стойки, дуги крыши, щиты.
  2. Наружные панели: боковины, крыша, крылья.
  3. Навесные детали: двери, капот, задние створки, сдвижная дверь.
  4. Остекление.
  5. Светотехника.
  6. Бамперы и наружная пластиковая отделка.
  7. Шасси: подвеска, колёса, тормоза (как габаритные объёмы).
  8. Силовой агрегат (габаритный объём моторного отсека).
  9. Интерьер: панель приборов, сиденья, перегородка, обивки.
  10. Уплотнители и крепёж.
- Режимы отображения:
  - цвет по слою, по материалу, по толщине листа, по статусу проверки;
  - **разнесённый вид** (детали раздвигаются от центра узла ползунком);
  - **сечения** — до трёх плоскостей X/Y/Z с заливкой среза и размерами;
  - «рентген» для всего, кроме выбранного.
- Инструменты: линейка (расстояние между двумя точками), минимальное
  расстояние между двумя деталями, угол, координаты точки в системе машины.
- Навигация как в CAD: вращение, сдвиг, зум к выделенному, стандартные виды
  (спереди, сбоку, сверху, изометрия), подложка-чертёж в ортопроекции.
- Мобильная версия: только просмотр слоёв, сечений и отчёта. Редактирование — на ПК.

### 1.3 Проверки
| Проверка | Что ищет | Как считается |
|---|---|---|
| Коллизия | Пересечение объёмов деталей | Пересечение треугольников через BVH, затем оценка глубины проникновения |
| Минимальный зазор | Детали ближе нормы (например, колесо и подкрылок < 20 мм) | Минимальное расстояние между сетками через BVH |
| Увеличенный зазор | Щель шире нормы (например, дверь–боковина > 5,0 мм) | Для пар из правил: профиль зазора вдоль стыка, выборка по точкам кромки |
| Перепад (flush) | Ступенька между соседними панелями | Расстояние по нормали вдоль стыка |
| Равномерность | Щель по стыку сужается или расширяется | Разброс значений по точкам кромки |
| Кинематика | Коллизии при движении | Прогон двери, капота, створок, сдвижной двери по траектории с шагом 1–2°/10 мм; колесо — ход подвески × поворот руля |
| Нормативы | Отклонения от стандартов | Правила по точкам: высота фар, номер, углы свеса, обзор |

- Каждое правило имеет пару деталей (или группы), тип проверки, пределы
  (мин., номинал, макс.), серьёзность и ссылку на источник нормы.
- Результат: список замечаний с серьёзностью (ошибка, предупреждение, информация),
  местом, фактическим и допустимым значением.
- Клик по замечанию: камера перелетает к месту, детали подсвечиваются, остальное
  становится прозрачным, при необходимости ставится сечение через точку.
- Тепловая карта зазоров на кромках: зелёный — в норме, жёлтый — у границы,
  красный — вне нормы.
- Проверки считаются в Web Worker, чтобы интерфейс не зависал. Повторный расчёт
  идёт только для изменённых деталей.
- Отчёт выгружается в CSV/JSON и в HTML-страницу с картинками мест.

### 1.4 Справочные нормы по умолчанию
Хранятся в `data/norms/*.json`, у каждой записи есть источник. Значения ниже
**типовые**, взятые из открытых справочников и стандартов, а не из закрытой
документации Fiat. В проекте их можно переопределить.

**Зазоры и перепады наружных панелей** (типовые нормы производителей,
справочники по кузовостроению):
| Стык | Зазор, мм | Перепад, мм |
|---|---|---|
| Дверь передняя – боковина / крыло | 4,0 ± 1,0 | 0 ± 1,0 |
| Дверь – дверь / сдвижная – стойка | 4,5 ± 1,0 | 0 ± 1,0 |
| Капот – крыло | 3,5 ± 1,0 | 0 ± 1,0 (капот не выше крыла) |
| Задние створки между собой | 5,0 ± 1,5 | 0 ± 1,5 |
| Фара – крыло / капот | 3,0 ± 1,0 | 0,5 ± 1,0 |
| Бампер – крыло | 1,5 ± 1,0 | 0 ± 1,5 |
| Задний фонарь – боковина | 2,0 ± 1,0 | 0 ± 1,0 |
| Равномерность зазора вдоль стыка | разброс ≤ 1,0 | — |

**Минимальные зазоры (безопасность и работоспособность)**:
| Пара | Мин. зазор, мм |
|---|---|
| Шина – подкрылок / арка во всём ходе подвески и повороте | 15–20 |
| Шина с цепью противоскольжения – арка | 25 (опционально) |
| Выпускная система – пол / топливный бак | 25 (без экрана), 12 (с экраном) |
| Двигатель – капот (зона удара пешехода) | 60–80 (ECE R127) |
| Подвижные панели – соседние детали при движении | 3 |
| Жгуты и трубки – острые кромки | 10 |

**Толщины листа (типовые для лёгких коммерческих машин)**:
| Деталь | Толщина, мм | Материал |
|---|---|---|
| Наружные панели дверей, капота, крыши | 0,7–0,8 | Сталь DC04/DX54, оцинкованная |
| Наружная боковина | 0,8 | DC04 |
| Внутренние панели дверей | 0,7–1,0 | DC03/DC04 |
| Стойки, пороги, усилители | 1,2–2,0 | HSLA 340–420 / DP600 |
| Лонжероны, поперечины пола | 1,5–2,5 | HSLA / DP600–DP800 |
| Пол | 0,8–1,0 | DC03 |

**Нормативы положения** (ГОСТ/ЕЭК ООН):
- Фары ближнего света — ECE R48: нижняя кромка ≥ 500 мм, верхняя ≤ 1200 мм, ≤ 400 мм от края габарита.
- Задние фонари, стоп-сигналы — ECE R48: высота 350–1500 мм; дополнительный стоп-сигнал по центру.
- Место для номерного знака — ECE R4 / ГОСТ Р 50577: 520 × 112 мм, высота 300–1200 мм.
- Остекление — ECE R43 (маркировка и зоны обзора), обзор водителя — ECE R125.
- Защита пешехода — ECE R127 (зазор под капотом).
- Эргономика водителя — SAE J1100 (размеры салона), манекен H-точки SAE J826.
- Задний защитный брус — ECE R58 для категории N1 при необходимости.

**Материалы** (`data/materials.json`): плотность, модуль упругости, предел
текучести — для расчёта массы и подсказок; стали DC01–DC06, HSLA, DP, алюминий
6016, ПП-EPDM для бамперов, ПК для рассеивателей, стекло.

Перед использованием каждую норму нужно сверить с актуальной редакцией
стандарта. В интерфейсе рядом с правилом показывается источник и пометка
«типовое значение».

### 1.5 Геометрия деталей
- Основной способ — **параметрические генераторы** деталей из общих
  «управляющих поверхностей» кузова: профиль сбоку, план, сечения. Меняется
  параметр, и все зависимые детали пересчитываются. Так стыки и зазоры
  заданы явно, а не подгоняются на глаз.
- Листовые детали строятся как оболочка с толщиной (срединная поверхность ± t/2),
  а не как одна бесконечно тонкая поверхность. Без этого нельзя считать коллизии.
- Кромки и фланцы строятся отдельно: отбортовка дверей, фланцы проёмов,
  места под уплотнители. По ним считаются зазоры и перепады.
- Импорт: glTF/GLB сразу; STEP/IGES позже через `occt-import-js`
  (OpenCascade в WebAssembly). Так в проект можно положить реальную CAD-деталь
  и проверить её с остальными.
- Система координат как в автопроме: X назад от передней оси (или от носа),
  Y влево/вправо, Z вверх, миллиметры. Отображение переводится в three.js.

## 2. Архитектура

```
index.html
src/
  app/           интерфейс: дерево, слои, панель свойств, отчёт, инструменты
  viewer/        three.js: сцена, камеры, сечения, разнесённый вид, подсветка
  model/         типы данных проекта, загрузка/сохранение, история изменений
  geometry/      управляющие поверхности, генераторы деталей, оболочки с толщиной
  parts/doblo/   описание деталей Doblò Cargo Maxi (генераторы + параметры)
  checks/        правила, движок проверок, кинематика, отчёт
  workers/       Web Worker для проверок
data/
  norms/         зазоры, минимальные зазоры, нормативы ЕЭК/ГОСТ (с источниками)
  materials.json
  projects/doblo-cargo-maxi/project.json
tests/           модульные тесты геометрии и проверок
docs/            этот план, описание формата проекта, руководство
```

- **Стек:** TypeScript + Vite, three.js, `three-mesh-bvh` (быстрые пересечения и
  расстояния), Web Workers. Тесты — Vitest. Всё собирается в статический сайт:
  его можно открыть локально или выложить на GitHub Pages.
- **Состояние:** одно хранилище проекта; интерфейс и 3D подписаны на изменения.
- **Производительность:** цель — до 500 деталей и 2 млн треугольников при 60 кадрах
  на ПК. Для этого нужны инстансинг одинаковых деталей (крепёж), упрощённые сетки
  для проверок и BVH, построенный один раз для каждой детали.

## 3. Этапы

Каждый этап заканчивается рабочей версией, скриншотами и проверкой на ПК и телефоне.

### Этап 0. Каркас приложения (1–2 дня)
- Vite + TypeScript, линтер, тесты, сборка статического сайта.
- Пустая сцена с сеткой, осями и системой координат машины.
- Загрузка и сохранение `project.json`.
- **Готово, когда:** проект открывается, сохраняется и загружается без потерь; тесты проходят.

### Этап 1. Модель данных и просмотр по слоям (3–4 дня)
- Типы: проект, узел, деталь, материал, правило, замечание.
- Дерево изделия и панель слоёв: показать, скрыть, прозрачно, изолировать, заблокировать.
- Панель свойств детали: код, материал, толщина, масса, статус.
- Раскраска по слою, материалу, толщине.
- Разнесённый вид и сечения по X/Y/Z.
- На этом этапе детали — простые габаритные объёмы, чтобы отладить интерфейс.
- **Готово, когда:** любую деталь можно найти в дереве, изолировать, рассечь и измерить.

### Этап 2. Справочник норм (2 дня)
- JSON-файлы норм из раздела 1.4 с источниками.
- Экран справочника: просмотр, поиск, переопределение значения в проекте
  (исходное значение и источник сохраняются).
- **Готово, когда:** каждое правило показывает значение, допуск и источник.

### Этап 3. Геометрия кузова Doblò (7–10 дней)
- Управляющие поверхности: профиль сбоку, план, сечения по чертежу Doblò 2015 Cargo LWB.
- Каркас в белом: пол с тоннелем и колёсными арками, лонжероны, пороги,
  стойки A/B/C/D, дуги крыши, моторный щит, задняя рамка проёма.
- Наружные панели: боковины, крыша, передние крылья, панель под лобовым стеклом.
- Навесные детали: двери (наружная и внутренняя панель, отбортовка), капот,
  сдвижная дверь с направляющими, задние створки 60/40.
- Остекление, светотехника, бамперы, решётка.
- Шасси габаритами: колёса 195/60 R16, подвеска, тормоза.
- Интерьер габаритами: панель приборов, сиденья с H-точкой, перегородка.
- Сверка с чертежом наложением во всех проекциях (инструмент уже есть).
- **Готово, когда:** силуэт совпадает с чертежом в пределах ±15 мм по основным
  линиям, а у каждой листовой детали есть толщина.

### Этап 4. Статические проверки (4–5 дней)
- BVH для всех деталей, движок в Web Worker.
- Коллизии, минимальные зазоры, увеличенные зазоры, перепады, равномерность по стыку.
- Правила для всех стыков из таблицы 1.4.
- Отчёт: таблица, фильтры, переход к месту, тепловая карта на кромках.
- Тесты движка на эталонных фигурах с известными расстояниями.
- **Готово, когда:** специально сдвинутая на 3 мм дверь даёт замечание
  «увеличенный зазор» с правильным значением ±0,2 мм.

### Этап 5. Кинематика (4–5 дней)
- Оси шарниров дверей, капота, задних створок; траектория сдвижной двери.
- Ход подвески и поворот руля: огибающая колеса против подкрылка.
- Анимация с проверкой на каждом шаге; в отчёт попадает угол или положение,
  где появилась коллизия.
- **Готово, когда:** открытие двери на 90° и 180° и полный ход колеса проверяются
  автоматически, результат воспроизводится.

### Этап 6. Нормативные проверки (2–3 дня)
- Высоты и положения светотехники (ECE R48), место под номер (ECE R4),
  углы въезда и съезда, дорожный просвет, зазор под капотом (ECE R127).
- **Готово, когда:** для каждой нормы есть правило с источником и результатом.

### Этап 7. Импорт, отчёты, версии (3–4 дня)
- Импорт glTF и STEP (через `occt-import-js`) с привязкой к узлу дерева.
- Отчёт HTML/CSV/JSON; сравнение двух версий проекта (что изменилось, какие замечания
  появились или исчезли).
- **Готово, когда:** импортированная деталь участвует в проверках наравне с остальными.

### Этап 8. Полировка и документация (2 дня)
- Горячие клавиши, мобильный режим просмотра, руководство пользователя, описание формата.

**Итого:** около 30–37 рабочих дней. Этапы 0–2 дают работающий просмотрщик по слоям,
этапы 3–4 — первую полезную проверку зазоров.

## 4. Риски и ограничения
- **Нет заводской CAD-модели Fiat.** Геометрия строится по чертежу, фото и
  открытым габаритам. Проверки показывают конфликты внутри нашей модели;
  для реального изделия нужно импортировать реальные CAD-данные (этап 7).
- **Нормы типовые.** Заводские допуски Fiat закрыты. Значения по умолчанию
  взяты из общих справочников и стандартов; перед применением их нужно сверить.
- **Точность в браузере.** Для зазоров 1–5 мм на машине длиной 4,7 м нужна
  аккуратная работа с точностью: хранить координаты в миллиметрах, считать
  в локальных системах деталей, а для проверок использовать сетки без упрощения
  в зонах стыков.
- **Скорость проверок.** Полная проверка всех пар — это O(n²). Отсекаем пары
  по габаритным рамкам и считаем только пары из правил и соседей по узлам.

## 5. Принятые решения
1. **Редактирование — через параметры.** Размеры, толщины, зазоры и оси петель
   меняются в панели свойств, деталь перестраивается и перепроверяется.
   Свободного перетаскивания нет: в инженерных системах геометрию задают
   параметрами и связями, а не мышью.
2. **Импорт CAD.** Формат проекта сразу допускает внешнюю геометрию. Первым идёт
   glTF/GLB, STEP подключается на этапе 7 через `occt-import-js`.
3. **Стандарты.** Основа — Правила ЕЭК ООН: ТР ТС 018/2011 ссылается на них
   напрямую, ГОСТ Р в основном их повторяют. Номер ГОСТ указывается рядом, где он есть.
   Зазоры и перепады панелей в стандартах не нормируются, это практика
   производителей: такие значения помечены как «практика проектирования».
4. **Репозиторий** перестроен под систему. Старая 3D-модель удалена, она
   сохранена в истории git (коммит `76650b1`).
5. **Система координат** — принятая в кузовостроении: X — назад от передней оси,
